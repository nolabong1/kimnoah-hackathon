# AI 공통 학습 설계도

## 목적

과제 기반 AI 학습자료와 퀴즈가 서로 다른 기준으로 내용을 만들지 않도록
동일한 최소 학습 계약을 사용한다. 별도 AI 호출이나 DB 저장 없이 계획과
과제의 기존 입력을 결정론적으로 정규화한다.

## 설계도 구성

- 과목명
- 계획의 주 학습목표
- 현재 과제의 초점과 범위
- 현재 수준에서 변환한 목표 깊이
- 예상 학습시간
- 고정된 세 가지 성공 기준

성공 기준은 다음 순서로 유지한다.

1. `explain`: 핵심 개념과 적용 조건을 자신의 말로 설명한다.
2. `apply`: 구체적인 예시나 문제 상황에 적용한다.
3. `differentiate`: 올바른 적용과 흔한 오해를 구분한다.

## 수준과 목표 깊이

- 현재 수준 1~3: `foundation`
- 현재 수준 4~7: `developing`
- 현재 수준 8~10: `advanced`

이 구간은 기존 1~10 수준 값을 바꾸지 않는다. AI가 설명과 평가 깊이를
일관되게 선택하도록 돕는 파생 신호다.

## 생성기별 사용

학습자료는 세 성공 기준을 주요 개념·상세 설명·학습 예시·자기 점검에
연결한다. 퀴즈는 5문항 안에서 설명 2문항, 적용 2문항, 오해 구분 1문항을
평가하도록 요청한다. 각 새 퀴즈 문항은 `evidence_key`를 저장하며 Pydantic과
Python 검증에서 정확한 2·2·1 분포가 아니면 생성 결과를 허용하지 않는다.

`learner_context`는 설계도의 범위를 바꾸지 않는다. 현재 과제와 관련된
취약점이 있을 때 설명 순서와 문항 초점을 조정하는 보조 문맥으로만 쓴다.

## 안전성과 비용

- 사용자·계획·과제 UUID를 포함하지 않는다.
- 문자열은 데이터로 취급하며 시스템 지침으로 실행하지 않는다.
- 별도 OpenAI 호출을 추가하지 않는다.
- DB 스키마와 저장 형식을 변경하지 않는다.
- 기존 과제 완료와 EXP 흐름을 변경하지 않는다.

## 현재 한계

현재 학습자료 과제와 퀴즈 과제가 서로 다른 제목·설명을 가지면 각 과제의
세부 범위도 다르다. 같은 설계도 형식과 계획 목표는 공유하지만, 생성된
학습자료 본문을 퀴즈의 직접 근거 원본으로 사용하지는 않는다. 이를 강제하려면
향후 계획 단계에서 과제 사이의 명시적 학습목표 ID 또는 자료-퀴즈 연결 저장이
필요하다.
