# AI 학습 코치 디자인 시스템 초안

> 상태: 승인된 v1 기준
>
> 작성 기준: 2026-08-17 저장소와 제공된 8개 참고 이미지
>
> 적용 범위: Streamlit 화면의 시각 체계와 정보 배치
>
> 제외 범위: 인증, 데이터베이스, 세션 상태, 학습계획, 퀴즈, EXP,
> 숙련도, 업적, 배지, 도전과제와 보상 규칙의 변경

## 1. 자료와 경로 상태

AGENTS.md와 작업 요청은 다음 경로를 시각 기준으로 지정한다.

- 디자인 시스템: `docs/design/DESIGN_SYSTEM.md`
- 참고 이미지: `docs/design/references/`

참고 이미지 8개는 정식 `docs/design/references/` 경로에 둔다. 이전
`design/DESIGN_SYSTEM.md`는 기존 링크를 위한 안내 파일로만 유지한다.

## 2. 참고 이미지 검토

### 이미지 1: 메인 랜딩과 카테고리 카드

- 짙은 배경의 큰 메시지 영역과 밝은 콘텐츠 영역을 명확하게 나눈다.
- 큰 제목, 짧은 보조 문장, 굵은 카드 제목으로 정보 위계가 분명하다.
- 세 개의 강한 컬러 카드는 같은 크기와 정렬로 비교가 쉽다.
- 3D 아이콘과 로고는 참고 제품의 브랜드 자산이므로 사용하지 않는다.

### 이미지 2: 강의 카탈로그와 혜택 카드

- 본문을 화면 전체로 늘리지 않고 가운데 약 1,100~1,200px 폭에 모은다.
- 카드 이미지, 제목, 설명, 버튼의 순서가 반복되어 탐색이 쉽다.
- 옅은 파랑과 옅은 회색으로 섹션 배경을 구분한다.
- 순위 배지처럼 작은 상태 요소를 카드 모서리에 배치한다.

### 이미지 3: 과정 목록

- 강한 단색 히어로 아래에 3열 과정 카드를 배치한다.
- 상태 배지, 과정명, 기간, 마감 정보가 같은 순서로 반복된다.
- 화면 가장자리보다 콘텐츠 칼럼의 좌우 여백을 크게 유지한다.
- 인물 사진, 브랜드 로고, 과정용 3D 일러스트는 복제하지 않는다.

### 이미지 4: 문서형 FAQ

- 왼쪽 로컬 목차와 오른쪽 본문을 분리해 긴 콘텐츠의 깊이를 줄인다.
- 선택한 항목만 옅은 강조 배경으로 표시한다.
- 본문 제목과 설명은 크게, 보조 카드와 메타데이터는 작게 표시한다.
- Streamlit에서는 고정형 목차보다 페이지 내 선택 위젯과 선택 콘텐츠
  렌더링으로 단순화한다.

### 이미지 5: 콘텐츠 자료실

- 상단 배너, 카테고리 선택, 섹션 제목, 카드 그리드가 반복되는 구조다.
- 카드 표면은 흰색 또는 옅은 회색이고 테두리와 그림자는 매우 약하다.
- 필터는 항상 보이되 콘텐츠보다 시각적 무게가 낮다.
- 외부 회사 로고와 실제 포트폴리오 이미지는 사용하지 않는다.

### 이미지 6: 과정 상세

- 진한 히어로에서 핵심 목표와 주요 행동 하나를 강조한다.
- 핵심 수치 세 개를 같은 크기의 밝은 카드로 가로 배치한다.
- 섹션마다 배경 명도를 크게 달리해 긴 페이지를 구획한다.
- 고정 하단 CTA와 픽셀 단위 히어로 구성은 Streamlit MVP에서 제외한다.

### 이미지 7: 가입 폼

- 좁은 폼 칼럼을 가운데 배치하고 주변 여백을 크게 둔다.
- 입력 라벨, 도움말, 입력 영역의 순서를 일관되게 유지한다.
- 앱의 인증 화면에는 개인정보 입력 항목을 추가하지 않고 현재 로그인과
  회원가입 필드만 같은 원칙으로 정돈한다.

### 이미지 8: 긴 읽기 콘텐츠

- 왼쪽 목차와 가운데 읽기 칼럼을 분리한다.
- 본문 폭을 좁혀 긴 문장의 가독성을 높인다.
- 작은 카테고리 배지, 큰 제목, 설명, 날짜, 본문의 위계가 뚜렷하다.
- 공유 버튼, 원본 영상, 브랜드 콘텐츠는 현재 제품 범위가 아니다.

## 3. 적용할 시각 원칙

1. 한 화면에 하나의 주요 목적과 하나의 대표 행동을 둔다.
2. 넓은 데스크톱 화면을 사용하되 긴 읽기·입력 콘텐츠는 제한된 폭에 둔다.
3. 흰색 표면, 옅은 회색 배경, 짙은 본문 글자와 하나의 강조색을 기본으로 한다.
4. 데이터는 메트릭, 과제는 카드, 보조 설명은 caption으로 역할을 나눈다.
5. 모든 날짜·과제·업적을 동시에 펼치지 않고 선택한 항목의 상세만 표시한다.
6. 색상만으로 상태를 전달하지 않고 아이콘 또는 텍스트를 함께 표시한다.
7. 테두리는 얇게, 그림자는 사용하지 않거나 매우 제한적으로 사용한다.
8. 이모지는 축하와 기존 배지처럼 의미가 있을 때만 유지하고, 일반 UI
   아이콘은 Material Symbols를 우선한다.
9. 무거운 divider를 반복하지 않고 제목, 카드, 여백으로 섹션을 구분한다.
10. 네이티브 Streamlit 요소와 테마를 우선하고 CSS는 첫 적용 범위에서 쓰지 않는다.

## 4. 제안 색상 체계

참고 제품의 빨강을 그대로 복제하지 않는다. AI 학습 코치의 독립적인
정체성을 위해 중립 배경에 인디고 계열 한 가지를 중심으로 사용한다.

| 역할 | 제안 색상 | 용도 |
| --- | --- | --- |
| 페이지 배경 | `#F7F8FC` | 인증 후 전체 배경 |
| 기본 표면 | `#FFFFFF` | 카드, 폼, 본문 |
| 보조 표면 | `#F1F3F8` | 사이드바, 입력 배경, 보조 영역 |
| Primary | `#5B4FE5` | 주요 버튼, 선택 상태, 핵심 진행률 |
| Primary 진한색 | `#4338CA` | 대비가 필요한 강조와 링크 |
| Secondary | `#0F8AA6` | 보조 데이터 강조, 차트 보조색 |
| 본문 글자 | `#171923` | 제목과 본문 |
| 보조 글자 | `#667085` | 설명, 날짜, 메타데이터 |
| 테두리 | `#E2E6EF` | 카드와 입력 경계 |
| 성공 | `#15803D` | 완료, 저장 성공 |
| 경고 | `#B45309` | 미래 과제, 주의 상태 |
| 오류 | `#C2413B` | 실패, 잘못된 입력 |
| 잠김/비활성 | `#98A2B3` | 비활성 버튼과 잠긴 항목 |

원칙:

- Primary는 한 화면에서 가장 중요한 행동과 현재 선택에만 사용한다.
- 성공·경고·오류 색은 의미 전달에만 사용하며 장식 색으로 사용하지 않는다.
- Primary 버튼의 흰 글자 대비와 본문 대비는 WCAG AA를 목표로 검토한다.
- 다크 모드는 MVP 첫 개편에 포함하지 않는다.

## 5. 타이포그래피

### 글꼴

- 추천: `Noto Sans KR` 400·500·600·700
- 대안: 배포 환경에서 외부 글꼴을 불러오지 못하면 Streamlit 기본
  `sans-serif`를 사용한다.
- 본문과 제목은 같은 글꼴군을 사용한다.

### 위계

| 단계 | 권장 크기/굵기 | 사용 위치 |
| --- | --- | --- |
| 페이지 제목 | 32px / 700 | 화면 최상단 한 번 |
| 주요 섹션 제목 | 24px / 700 | 화면의 큰 작업 구간 |
| 카드/하위 섹션 제목 | 18~20px / 600 | 카드와 선택 상세 |
| 본문 | 15~16px / 400 | 설명과 결과 |
| 강조 본문 | 15~16px / 600 | 과제명, 핵심 값 |
| Caption | 13~14px / 400 | 날짜, 상태, 도움말 |

Streamlit 구현에서는 `st.title` 또는 `st.header`를 페이지마다 하나만 사용하고,
`st.subheader`, `st.markdown("**...**")`, `st.caption` 순으로 하위 위계를 만든다.
같은 카드 안에서 여러 `###` 제목을 중첩하지 않는다.

## 6. 간격과 콘텐츠 폭

### 간격 토큰

| 토큰 | 값 | 사용 예 |
| --- | --- | --- |
| XXS | 4px | 아이콘과 짧은 라벨 |
| XS | 8px | 라벨과 도움말 |
| S | 16px | 카드 내부 요소 |
| M | 24px | 카드 사이, 작은 섹션 |
| L | 32px | 주요 섹션 사이 |
| XL | 48px | 페이지의 큰 구획 |

네이티브 Streamlit에서는 `gap="small"`을 카드 내부 기본값,
`gap="medium"`을 주요 그룹 사이 기본값으로 사용한다. `st.space()`는
필요한 예외에서만 사용한다.

### 폭

- 앱 설정: `layout="wide"` 유지
- 대시보드 최대 본문 폭: 1,280px 권장
- 일반 폼과 결과 화면: 1,080~1,200px 권장
- 긴 Markdown 읽기 영역: 840~960px 권장
- 로그인/회원가입 폼: 480~560px 권장
- 사이드바: Streamlit 기본 폭을 유지하고 별도 CSS로 강제하지 않는다.

`st.container(width=<px>)`와 상위 중앙 정렬 컨테이너를 이용하며,
화면 전체에 고정 폭을 일괄 적용하지 않는다.

## 7. 컴포넌트 규칙

### 페이지 헤더

- 페이지 제목 한 줄
- 사용자가 이 화면에서 할 수 있는 일을 설명하는 짧은 caption 한 줄
- 보조 행동은 오른쪽 action row에 배치
- 제목 앞 장식용 이모지는 제거하고 Material 아이콘은 내비게이션에서 사용

### 카드

- 기본은 `st.container(border=True)`를 사용한다.
- 카드 배경, radius, 테두리는 전역 테마로 통일한다.
- 카드 내부 순서는 `caption → 제목 → 설명 → 진행/상태 → 행동`을 기본으로 한다.
- 카드 안에 카드가 세 단계 이상 중첩되지 않도록 한다.
- 목록은 모든 상세를 펼치지 않고 선택한 항목 하나의 상세를 렌더링한다.

### 메트릭

- 한 행에 최대 네 개를 사용한다.
- `st.metric(border=True)`를 사용한다.
- 값의 의미가 다른 메트릭을 단순히 칸 수를 맞추려고 함께 두지 않는다.
- 예상 시간은 실제 학습시간으로 표현하지 않는다.

### 버튼

- Primary: 화면 또는 카드의 대표 제출·저장 행동 한 개
- Secondary: 다시 생성, 다음 힌트, 일반 이동
- Tertiary: 취소, 보조 동작
- Destructive: 삭제 확인 dialog 안에서만 강하게 표시
- 아이콘은 Material Symbols를 사용하고 버튼 라벨만으로도 의미가 전달되어야 한다.
- 반복 요청을 막는 기존 disabled와 in-progress 상태를 보존한다.

### 입력

- 접근 가능한 라벨을 유지하고 빈 라벨을 사용하지 않는다.
- 설명은 placeholder에만 의존하지 않고 `help` 또는 `caption`으로 제공한다.
- 관련 입력은 `st.form`으로 묶어 불필요한 rerun과 API 호출을 막는다.
- 2~5개의 단일 선택은 `st.segmented_control`, 긴 목록은 `st.selectbox`,
  왼쪽 세로 탐색 목록은 `st.radio`를 사용한다.
- 7일 시간 입력처럼 반복 입력은 최대 2열을 유지한다.

### 진행 표시

- `st.progress`에는 현재 값과 목표 값을 텍스트로 함께 표시한다.
- 숙련도, EXP, 도전과제 진행률은 같은 형태를 사용하되 라벨로 구분한다.
- 완료는 성공 메시지, 취약/주의는 경고 메시지 또는 배지로 보조한다.
- 진행률 색만으로 성공과 실패를 판단하게 만들지 않는다.

### 내비게이션

- 페이지가 8개이므로 현재 `st.navigation(position="sidebar")` 구조를 유지한다.
- 그룹은 `오늘 학습`, `계획`, `AI 도구`, `성장`을 유지한다.
- 사이드바에는 내비게이션, 간단한 사용자/EXP 요약, 로그아웃을 둔다.
- 개발용 테스트 버튼은 페이지 본문에서 제거하고, 사이드바 하단의 지연 실행
  `테스트 도구` expander 하나에 모은다.
- 페이지 내부 단계와 날짜 선택을 전역 내비게이션에 추가하지 않는다.
- 참고 이미지의 상단 GNB를 복제하지 않는다.

### Dialog

- 삭제, 최종 답 확인, 완료 피드백처럼 사용자의 집중이 필요한 경우만 사용한다.
- 제목, 결과/위험 설명, 영향 범위, 취소/확인 버튼 순서를 유지한다.
- 삭제와 되돌릴 수 없는 동작에는 명시적 확인 문구를 둔다.
- 한 실행에서 하나의 dialog만 연다는 Streamlit 제약을 따른다.

## 8. 화면 상태 규칙

### Empty

- 무엇이 없는지 한 문장으로 설명한다.
- 사용자가 다음에 할 수 있는 행동이 있으면 하나만 안내한다.
- 빈 공간을 큰 일러스트로 채우지 않는다.

### Loading

- 제출/API/DB 저장에는 기존 spinner와 요청 중 disabled 상태를 유지한다.
- 대시보드의 독립적인 느린 카드에는 추후 `st.skeleton`과 fragment를 검토한다.
- 로딩 중 같은 요청을 다시 실행하지 않는다.

### Disabled

- 퀴즈 만점 조건처럼 이유가 있는 disabled 버튼은 `help`로 이유를 제공한다.
- 비활성 색상만으로 이유를 전달하지 않는다.

### Success

- 저장·완료 직후 짧은 피드백은 toast 또는 success를 사용한다.
- 완료 상태처럼 계속 보여야 하는 정보는 카드 내부 상태로 유지한다.
- 기존 EXP 및 레벨업 dialog와 보상 애니메이션 동작을 변경하지 않는다.

### Warning

- 미래 과제 완료, 데이터 갱신, 되돌릴 수 있는 위험에 사용한다.
- 오류처럼 보이지 않도록 행동 선택을 함께 제공한다.

### Error

- 사용자가 할 수 있는 다음 행동을 한국어로 안내한다.
- API 키, 원시 응답, stack trace는 표시하지 않는다.
- 이번 시각 개편에서는 예외 처리와 DB 동작 자체를 바꾸지 않는다.

## 9. 게임화 표현

- 레벨, EXP, 연속 학습은 사이드바에서 간단히 유지한다.
- 오늘 학습 화면에는 오늘 도전과 최근 배지만 요약한다.
- 업적과 도전과제 전체 내용은 성장 화면에서 카드로 표시한다.
- 배지 카드에는 아이콘, 이름, 희귀도, 잠금/획득 상태를 같은 순서로 표시한다.
- 잠긴 비밀 업적의 정보 비공개 규칙을 그대로 유지한다.
- 희귀도는 색상뿐 아니라 텍스트로 표시한다.
- 기존 카탈로그의 배지 아이콘은 유지하되 참고 이미지의 3D 아이콘은 사용하지 않는다.
- 축하 효과는 실제 해금·완료 순간에만 사용하고 일반 화면 장식으로 반복하지 않는다.

## 10. 반드시 보존할 동작

시각 개편은 다음 동작을 변경하지 않는다.

- 인증과 브라우저 `sessionStorage` 복원
- 사용자별 데이터 소유권, RLS와 repository 호출
- 계획 생성·미리보기·명시적 저장 순서
- 선택한 오늘 학습 계획과 과제의 세션 상태
- 미래 과제 완료 재확인
- 퀴즈 만점 전 완료 잠금과 재응시 정책
- 과제당 AI 학습자료 하나와 재생성 갱신 정책
- 숙련도 계산, 취약 개념, 자동 복습과 간격 반복 규칙
- 과제 완료 10 EXP, 오늘 전체 완료 20 EXP와 중복 방지
- 레벨, 연속 학습, 업적, 도전과제와 보상 수령 규칙
- AI 튜터의 세 단계 힌트, 정답 확인과 API 호출 횟수
- 주간 회고 스냅샷, 다음 계획 미리보기와 명시적 저장
- 테스트 초기화와 테스트 완료 RPC 동작
- 모든 사용자 날짜 계산의 `Asia/Seoul` 기준

## 11. 복제하지 않을 참고 제품 자산

- SPARTA Club, 내일배움캠프와 관련 로고·워드마크
- 참고 제품의 정확한 빨강과 브랜드 조합
- 과정 카드의 3D 일러스트와 아이콘
- 인물 사진, 기업 로고, 포트폴리오 썸네일과 영상 이미지
- 참고 사이트의 문구, 과정명, 마케팅 카피
- 문의하기 위젯과 브랜드 채팅 아이콘
- 참고 사이트의 고유한 히어로 도형과 배너 구성

## 12. Streamlit에서 제외하거나 단순화할 상호작용

- 픽셀 고정형 상단 GNB와 메가 메뉴: 기존 사이드바 내비게이션으로 유지
- 복잡한 hover 애니메이션과 카드 전환: 선택 위젯과 rerun으로 대체
- 3D 아이콘 애니메이션: Material Symbols와 기존 배지 아이콘 사용
- 화면 하단 고정 CTA: 해당 섹션의 action row에 배치
- 다단 sticky 목차: 왼쪽 선택 목록 또는 segmented control로 대체
- masonry/무한 스크롤 카드 목록: 제한된 그리드 또는 선택 상세로 대체
- 브라우저 전체 폭의 이미지 히어로: 간결한 페이지 헤더와 핵심 메트릭으로 대체
- 입력 필드의 픽셀 단위 커스텀 외형: Streamlit 전역 테마와 네이티브 입력 사용

## 13. 최소 재사용 구조 제안

승인 후 첫 구현은 다음 세 파일 범위로 제한한다.

1. `.streamlit/config.toml`
   - 색상, 글꼴, radius, 테두리, 사이드바 등 전역 토큰만 정의
   - light 테마만 우선 제공

2. `views/ui_components.py`
   - 데이터베이스와 세션 상태를 알지 않는 작은 표시 helper만 제공
   - 후보: `page_header`, `metric_row`, `empty_state`, `action_row`,
     `content_frame`
   - 버튼 클릭, repository 호출, EXP 계산은 helper에 넣지 않음

3. 대표 화면 한 개
   - `views/dashboard_view.py`에만 새 토큰과 helper를 먼저 적용
   - `app.py`의 페이지 구성과 인증 흐름은 변경하지 않음

초기 단계에서는 사용자 정의 CSS, 새 프런트엔드 패키지, 커스텀 component를
추가하지 않는다. 네이티브 Streamlit으로 표현할 수 없는 요구가 실제로
확인될 때만 별도 승인을 받는다.

## 14. 페이지별 적용 계획

### 1단계: 대표 화면 — 오늘 학습

- 페이지 헤더, 계획 선택, KPI, 진행률의 위계를 통일한다.
- 현재 3영역 구조인 `과제 선택 / 선택 과제 / 학습 진단·성장`을 유지한다.
- 선택 과제만 상세 렌더링하는 현재 동작을 보존한다.
- 빈 일정, 완료, 퀴즈 잠금, 로딩·오류 상태를 디자인 시스템 기준으로 정돈한다.
- 기존 완료·퀴즈·학습자료·EXP 호출은 수정하지 않는다.
- AppTest와 수동 스크린샷 비교 후 다음 화면으로 진행한다.

### 2단계: 저장된 계획

- 계획 요약과 위험 동작을 분리한다.
- 현재 모든 날짜 expander를 렌더링하는 구조를 왼쪽 날짜 선택과 오른쪽
  선택 날짜 상세의 2영역으로 바꾼다.
- 오늘 날짜 기본 선택, 완료 후 선택 날짜 유지, 미래 과제 확인 상태를 보존한다.
- 테스트 도구는 페이지 본문에서 제거하고 사이드바 공통 expander로 이동한다.

### 3단계: 계획 만들기와 주간 회고

- 긴 입력 폼을 제한 폭 컨테이너에 배치한다.
- 7일 시간 입력은 2열을 유지한다.
- 생성 결과와 저장 행동을 별도 구간으로 분리한다.
- 주간 회고의 1~5단계 구조는 유지하되 현재 단계와 저장된 결과를 더 선명하게 한다.

### 4단계: AI 복습 자료와 단계별 힌트 튜터

- 설정 입력과 생성 결과의 폭을 분리한다.
- 긴 Markdown은 읽기 폭을 제한한다.
- 힌트 단계, 정답 확인, 수정 풀이 피드백을 카드 위계로 통일한다.
- API 호출을 일으키는 버튼과 세션 내 이동 버튼을 시각적으로 구분한다.

### 5단계: 과목별 숙련도

- 상단 KPI와 과목 비교를 대표 대시보드 패턴으로 통일한다.
- 선택 과목의 개념 카드를 2열 또는 제한된 목록으로 검토한다.
- 숙련도와 취약 상태를 텍스트와 진행률로 함께 표시한다.

### 6단계: 업적·도전과제

- 도전과제, 업적, 배지 탭의 카드 구조와 정보 순서를 통일한다.
- 완료·수령 가능·수령 완료·잠김 상태를 명확히 분리한다.
- 대표 배지 세 슬롯과 컬렉션의 반복 스크롤을 줄인다.
- 보상 판정과 RPC 호출은 변경하지 않는다.

### 7단계: 인증, 공통 dialog와 전체 회귀 검사

- 로그인/회원가입을 좁은 중앙 폼으로 정돈한다.
- 완료, 삭제, 정답 확인 dialog의 제목·설명·행동 순서를 통일한다.
- 전체 페이지의 빈 상태, 오류, loading, disabled 상태를 재검토한다.
- Python compile, import, unittest, AppTest와 기존 수동 시나리오를 실행한다.

## 15. 가정과 미결정 사항

### 현재 가정

- 데스크톱 화면이 우선이며 모바일 전용 최적화는 이번 범위가 아니다.
- 기존 사이드바 그룹과 페이지 수는 유지한다.
- 참고 이미지의 디자인 원칙만 사용하고 브랜드 정체성은 새로 정의한다.
- 초기 구현은 light 테마와 네이티브 Streamlit 요소만 사용한다.
- 오늘 학습 화면을 전체 개편의 대표 화면으로 사용한다.

### 승인된 기본 결정

1. Primary 색상은 인디고 `#5B4FE5`를 사용한다.
2. `Noto Sans KR` 원격 글꼴을 사용하고 실패 시 sans-serif로 대체한다.
3. 최대 폭은 대시보드 1,280px / 일반 1,120px / 읽기 900px를 기준으로 한다.
4. 참고 이미지는 정식 `docs/design/references/`에서 관리한다.
5. 이전 디자인 문서는 정식 문서 안내 파일로 유지한다.
6. 테스트 도구는 모든 페이지에서 접근 가능한 사이드바 하단의 지연 실행
   expander에 유지한다.
7. 로그인 화면에도 같은 인디고 테마를 적용한다.
8. MVP 첫 개편에서는 다크 모드를 제외한다.
