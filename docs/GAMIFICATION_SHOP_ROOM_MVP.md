# 코인·상점·학습방 꾸미기 MVP 기획

> 상태: 승인 완료, 8단계 구현 완료·Supabase 적용 및 수동 검증 대기
>
> 작성일: 2026-08-17
>
> 범위: 코인 경제, 꾸미기 상점, 인벤토리, 고정 슬롯 학습방,
> 수집 도감과 초기 에셋 15종

## 1. 목표

기존 `EXP → 레벨`, 업적, 도전과제, 대표 배지 흐름을 변경하지 않고
학습 행동에 사용할 수 있는 꾸미기 보상을 추가한다.

```text
학습 완료
→ 코인 획득
→ 상점에서 아이템 구매
→ 학습방에 장착
→ 컬렉션 수집률 상승
```

코인은 학습 진행을 우회하는 수단이 아니다. 코인으로 EXP, 숙련도,
과제 완료, 퀴즈 정답, AI 호출을 구매할 수 없다.

## 2. MVP 범위

### 포함

- 꾸미기 전용 재화 `코인`
- 서버 검증 기반 코인 지급과 차감 원장
- 고정 가격 상점
- 사용자 인벤토리
- 한 개의 개인 학습방
- 일곱 개의 고정 장착 슬롯
- 초기 판매 아이템 15종
- 보유 수와 전체 수를 보여주는 수집 도감
- 새 사용자와 기존 사용자에게 동일하게 한 번 지급하는 시작 코인

### 제외

- 가챠와 확률형 상품
- 유료 결제
- 사용자 간 거래와 선물
- 아이템 판매·환불
- 기간 한정 상품과 시즌 패스
- 자유 드래그, 회전, 크기 조절
- 여러 개의 학습방 저장
- 코인과 EXP 상호 변환

## 3. 재화 정의

| 항목 | 기준 |
| --- | --- |
| 이름 | 코인 |
| 표시 | `🪙 120` |
| 용도 | 상점 꾸미기 아이템 구매 전용 |
| 최소 잔액 | 0 |
| 시작 지급 | 사용자당 30코인 한 번 |
| 지급 기준 시간대 | Asia/Seoul |
| 감사 추적 | 모든 증감은 변경 불가능한 원장에 기록 |

시작 코인은 `onboarding:shop_v1`과 같은 고정 source key로 한 번만
지급한다. 기존 사용자와 신규 사용자에게 같은 기준을 적용한다.

## 4. 코인 획득 규칙

| 행동 | 코인 | 중복 방지 및 제한 |
| --- | ---: | --- |
| 일반 또는 자동 복습 과제 완료 | 5 | 과제당 한 번, 하루 최대 25코인 |
| 오늘 활성 과제 전체 완료 | 10 | 서울 날짜당 한 번 |
| 일간 도전과제 보상 수령 | 10 | 도전과제당 한 번 |
| 주간 도전과제 보상 수령 | 30 | 도전과제당 한 번 |
| 업적 해금 | 0 | 기존 EXP·배지 보상 유지 |
| 퀴즈 제출 | 0 | 퀴즈 과제 완료 시 과제 코인만 지급 |
| 자료·튜터·회고 생성 | 0 | AI 호출 반복을 보상으로 사용하지 않음 |

과제 완료 코인의 일일 상한은 계획을 반복 생성하여 재화를 과도하게
획득하는 것을 줄인다. 기존 과제 10 EXP와 오늘 완료 20 EXP 규칙은
변경하지 않는다.

테스트용 계획 완료 기능도 실제 완료 RPC를 통과하므로 코인 이벤트를 만들 수
있다. `reset_today_test_progress`는 해당 테스트로 생성된 코인 원장과 잔액을
함께 되돌려야 한다.

## 5. 가격과 진행 속도

목표 진행 속도는 다음과 같다.

- 첫 학습일 안에 첫 소품 구매
- 보통 아이템은 학습 1~3일
- 희귀 아이템은 학습 4~7일
- 모든 초기 아이템 수집은 여러 주가 필요

| 희귀도 | 권장 가격 | 역할 |
| --- | ---: | --- |
| 일반 | 30~60 | 빠른 첫 구매와 기본 조합 |
| 고급 | 70~110 | 며칠 동안 모아 구매하는 목표 |
| 희귀 | 140~180 | 주간 목표 성격의 수집품 |

상점 가격과 코인 보상은 서버 카탈로그가 정한다. Streamlit 클라이언트는
가격이나 차감량을 RPC에 전달하지 않는다.

## 7. 학습방 슬롯

| layer | 슬롯 키 | 역할 |
| ---: | --- | --- |
| 0 | `background` | 벽지와 창밖 분위기 |
| 10 | `floor` | 바닥 또는 바닥 전체 러그 |
| 30 | `desk` | 중앙 학습 책상 |
| 40 | `chair` | 책상 앞 의자 |
| 50 | `decor_left` | 왼쪽 소품 |
| 50 | `decor_right` | 오른쪽 소품 |
| 60 | `accent` | 펫, 트로피, 특별 수집품 |

사용자는 보유 아이템만 선택할 수 있다. 장착은 `학습방 저장하기`를 누를 때
서버 RPC에서 소유권, 슬롯 호환성, 중복 장착을 검증한 뒤 저장한다.

## 8. 시각 스타일

초기 에셋은 다음 스타일을 사용한다.

- 밝고 아늑한 아이소메트릭 3D 공부방
- 앱 Primary 인디고와 라벤더를 포인트로 사용
- 흰색·밝은 회색 중심의 기본 표면
- 장난감처럼 과장된 비율이지만 유아용 표현은 피함
- 하나의 카메라 시점, 광원 방향, 그림자 강도를 모든 에셋에 고정
- 이미지 안에 텍스트, 로고, 다른 서비스 캐릭터를 넣지 않음
- 참고 디자인의 브랜드 에셋이나 캐릭터를 복제하지 않음

## 9. 에셋 제작 규격

MVP에서는 좌표 계산을 줄이기 위해 모든 장착 에셋을 동일한 전체 캔버스
크기의 투명 오버레이로 제작한다.

| 종류 | 규격 | 형식 |
| --- | --- | --- |
| 기본 방 | 1600×900 | WebP |
| 장착 오버레이 | 1600×900, 투명 배경 | PNG |
| 상점 썸네일 | 256×256 | WebP |
| 잠금 썸네일 | 원본 썸네일을 UI에서 흐리게 처리 | 별도 파일 없음 |

전체 캔버스 오버레이는 파일 크기가 조금 커지지만, Streamlit에서 Pillow로
레이어를 합성할 때 위치 오차가 없고 구현과 검증이 단순하다.

```text
assets/
  study_room/
    base/
      room_default.webp
    items/
      backgrounds/
      floors/
      desks/
      chairs/
      decorations/
      accents/
    thumbnails/
    catalog.json
    ASSET_LICENSES.md
```

`catalog.json`은 `item_key`, 이름, 카테고리, 슬롯, 희귀도, 가격,
오버레이 경로, 썸네일 경로, layer를 가진다. AI 생성 에셋도 사용 모델,
생성일, 후처리 여부를 `ASSET_LICENSES.md`에 기록한다.

## 10. 상점과 학습방 UI

기존 게임화 화면에 다음 탭을 추가한다.

- `상점`: 전체 아이템, 카테고리 필터, 가격, 보유 상태와 구매
- `내 아이템`: 보유 아이템과 장착 여부
- `학습방`: 합성된 방 미리보기와 슬롯 선택
- `컬렉션`: 전체 15종 중 수집률과 잠긴 아이템

상점 카드의 정보 순서는 다음으로 통일한다.

```text
썸네일 → 희귀도·카테고리 → 아이템 이름 → 가격 → 보유 상태 → 구매 행동
```

학습방은 데스크톱 기준 왼쪽 미리보기, 오른쪽 슬롯 설정의 2열 구조를
사용한다. 자유 드래그 대신 selectbox와 명시적 저장 버튼을 사용한다.

미리보기는 기본 방과 선택한 1600×900 투명 오버레이를 브라우저 요청마다
유료 API 호출 없이 로컬에서 합성한다. 좌우 소품은 유효 픽셀을 각 슬롯의
고정 중심점으로 이동하여 하나의 소품 에셋을 두 위치에서 사용할 수 있다.

## 11. 이후 데이터 구조

구현 단계에서 다음 사용자 소유 테이블을 검토한다.

- `user_coin_wallets`: 현재 잔액과 누적 획득·사용량
- `coin_transactions`: 멱등 source key를 가진 코인 원장
- `shop_items`: 서버가 신뢰하는 상품 카탈로그
- `user_inventory`: 영구 소유 아이템
- `user_study_rooms`: 검증된 일곱 슬롯 장착 상태

코인 지급, 구매, 장착은 모두 `security definer` RPC에서 처리한다.
RPC는 빈 안전 `search_path`, `auth.uid()` 검증, `authenticated` 실행 권한,
행 잠금, 잔액 0 이상 제약과 source key 멱등성을 가져야 한다.

## 12. 구현 순서

1. 본 문서 승인
2. 코인 지갑·원장 모델과 SQL 마이그레이션
3. 과제 완료·도전과제 수령 RPC에 코인 지급 연결
4. 테스트 초기화의 코인 원장 역산 보강
5. 상점 카탈로그·인벤토리와 원자적 구매 RPC
6. 상점·인벤토리 Streamlit UI
7. 초기 에셋 제작과 catalog 검증
8. 고정 슬롯 학습방 저장·합성 UI
9. 컬렉션 도감
10. 전체 통합 테스트와 경제 수치 조정

각 단계는 기존 EXP, 레벨, 연속 학습, 과제 완료, 일일 보너스 규칙을
그대로 보존한다.
